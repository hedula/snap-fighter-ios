# Review Change

Review for correctness before declaring done.

1. Identify the change scope and baseline.
2. Check compliance with `AGENTS.md`, accepted decisions, and relevant specs.
3. Inspect the actual diff or changed files.
4. Verify behavior with the smallest relevant checks.
5. Report findings first, ordered by severity.
6. If no issues are found, say so and name any residual risk.

Separate spec mismatch, code quality, testing gaps, and operational risk.
