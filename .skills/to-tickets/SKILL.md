# To Tickets

Split work into independently useful pieces.

1. Read the accepted spec or plan first.
2. Prefer vertical slices that deliver observable behavior.
3. Keep each ticket small enough for one focused coding session.
4. Record dependencies only when real order matters.
5. Include acceptance criteria and verification for each ticket.
6. Put task breakdowns under `.development_document/4_task/`.

Avoid splitting by layers only, such as database, API, UI, and tests, unless the work is purely mechanical.
